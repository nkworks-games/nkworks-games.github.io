# 並行地球：Blender の場面づくり

`scene.py` は、計算データ（スタジオの「Blender用 JSON」）から、ある星・ある年・ある島の入り江の景色を組み立てて、Cycles で描きます。

- 地形・海・木・岩・家・舟・空は、すべてこのスクリプトが作ります。外部の素材（画像・モデル・HDRI）は使わないので、利用条件の確認は不要で、どの環境でも同じ景色になります。
- 同じ引数なら同じ景色です（乱数の種は `--seed`、既定は7）。
- このフォルダは名前が `_` で始まるので、サイト（GitHub Pages）には公開されません。

## 使い方

1. 計算データを用意します。スタジオで条件を選んで「Blender用 JSON」を押すか、コマンドで書き出します。

   ```bash
   node heikou-chikyu/studio/_dev/export-blender.js data.json '{"policy":"demand","storm":true}'
   ```

2. Blender で描きます（Mac の例。`--gpu` で Metal を使う）。

   ```bash
   /Applications/Blender.app/Contents/MacOS/Blender -b -P heikou-chikyu/_blender/scene.py -- \
     --data data.json --planet reference --year 24 --island D --out d-y24.png --gpu --blend d-y24.blend
   ```

   Blender 本体がない環境では、Python の `bpy` パッケージ（Blender 5.0）でも動きます：`python scene.py -- --data ...`

3. 細かく直したいときは、`--blend` で保存した .blend を Blender で開きます。

| 引数 | 意味 | 既定 |
|---|---|---|
| `--data` | 計算データ（Blender用 JSON）。なければ手つかずの状態 | なし |
| `--planet` / `--year` / `--island` | どの星・何年目・どの島か | reference / 0 / D |
| `--out` | 描いた画像。`--anim` のときは連番画像の頭（`f_` → `f_0001.png`…） | heikou-scene.png |
| `--res` / `--samples` | 解像度と、1画素あたりの試行回数 | 1920x1080 / 256 |
| `--preview` | 960×540・48回で速く描く（構図や色の確認用） | なし |
| `--camera` | `drone`（入り江の上空16m）か `boat`（水面から2.4m） | drone |
| `--anim` `--seconds` `--fps` | 沖から入り江へ近づくカメラ移動を描く | 12秒・24コマ |
| `--sun-elevation` / `--sun-azimuth` | 太陽の高さと方位（北0・東回り） | 16° / -130°（南西） |
| `--gpu` | GPU で描く（Metal・OptiX・CUDA・HIP の順に探す） | CPU |
| `--border` | 画面の一部だけ描く（左,下,右,上を0〜1で） | なし |
| `--blend` | 編集できる .blend も保存する | なし |

連番画像から動画を作る例：`ffmpeg -framerate 24 -i f_%04d.png -c:v libx264 -pix_fmt yuv420p -crf 18 out.mp4`

## 第1回のショットを描く（shots.py）

`shots/ep1.json` は、計算の記録から作ったショットの一覧（43カット。`_sim/export_shots.py` で作り直せる）。`shots.py` がそれを読んで、海岸・沖・群島・惑星の場面を組み立てて描く。

```bash
# 構図の確認（960×540・静止画・1カット1分前後）
/Applications/Blender.app/Contents/MacOS/Blender -b -P heikou-chikyu/_blender/shots.py -- --still --preview --gpu --out ~/heikou-preview

# 本番（1920×1080・64回・1コマおきに描いて間を補う・中断したら同じコマンドで続きから）
/Applications/Blender.app/Contents/MacOS/Blender -b -P heikou-chikyu/_blender/shots.py -- --gpu --step 2 --resume --out ~/heikou-renders

# 連番画像をカットごとの mp4 に（1コマおきの分は動きから補う）
python3 heikou-chikyu/_sim/frames_to_mp4.py ~/heikou-renders
```

**第1回の本番は `render_ep1.sh` でまとめて描ける**（第4版で使う35ショットだけ・1920×1080・32回・GPU・1コマおき・止めても続きから。海岸のカットは M5 で1コマ約45秒（64回のとき）、32回で約4割短い）。
描いたものは `heikou-chikyu/_sim/out/renders/final/` に集まる。そのあと、クラウドで作った材料一式（heikou-ep1-pack.zip：図の動画・字幕・表示・字体）を
`heikou-chikyu/_sim/` で展開して、`python3 heikou-chikyu/_sim/make_roughcut.py` でつなぐ（くわしくは zip の中の `out/組み立ての手順.md`）。

```bash
bash heikou-chikyu/_blender/render_ep1.sh              # 全部（止めても同じコマンドで続きから）
bash heikou-chikyu/_blender/render_ep1.sh 013 070      # 一部だけ
```

| 引数 | 意味 | 既定 |
|---|---|---|
| `--only 003,013` | 一部のカットだけ | すべて |
| `--still` | 動くカットも、最初の1コマだけ描く | なし |
| `--preview` | 960×540・24回 | なし |
| `--samples` | 1画素あたりの試行回数 | 64 |
| `--step 2` | 2コマに1コマだけ描く（描く時間が半分。間は `frames_to_mp4.py` が補う） | 1 |
| `--resume` | 描き終えたコマ・静止画は飛ばす | なし |
| `--blend` | 組み立てた場面を .blend でも保存する | なし |
| `--anchors` | 描かずに、矢印の先の点の記録（anchors_cutNNN.json）だけ書く | なし |

- 矢印や名前を重ねるカット（ショットに `anchors` があるもの：013・049・070・076・221）は、描くときに `anchors_cutNNN.json`（矢印の先の点が、コマごとに画面のどこに来るか）も同じ場所に書く。mp4・静止画といっしょに `heikou-chikyu/_sim/out/renders/final/` へ置くと、`make_roughcut.py` が矢印をカメラの動きに合わせて重ねる。描き直さずに点の記録だけ作るときは `--anchors`。
- 海岸のカットのカメラと注視点の高さは「その場所の地面（海なら海面）からの高さ」。島の形は乱数の種ごとに少し違うので、絶対の高さで書くと地面に埋まることがある。絶対の高さで書きたいときは `"camera": {"absolute": true, ...}`。
- 動くカットは合わせて 316秒（7,584コマ）。M5 の 1コマ 21.7秒で全部描くと約46時間かかるので、`--step 2` で約23時間にする。夜に流して、朝に `--resume` のまま続きを流せばよい。
- 描く順番の目安：先に静止画のカット（7つ）と短いカットで色と構図を確かめ、それから長いカットを流す。

## 計算データ → 景色の対応（仮置き）

生物量と画面上の本数は別の量なので、そのまま比例させずに次の規則で対応させています。どれも仮置きで、見せ方に合わせて変えてかまいません。

| 計算データ（その島・その年） | 景色 |
|---|---|
| 森の指数 F（開始時を1） | 木の本数は F^0.75 の割合。集落から行きやすい所（近く・低い所）ほど先に切られ、境目はぼかす。残る木の大きさは ×(0.72＋0.28×本数の割合)。切り跡の約14％には若木が育ち、残りの切り跡の約35％に切り株が残る |
| 人口 | 家の数＝人口÷6.5（3〜60軒） |
| 船（木・軽殻石） | 桟橋の沖に停泊する大きな船。軽殻石の船は白い船体。小さな丸木舟5艘は景色の一部として常に置く |
| 藻類の指数 | 水の色（多いほど少し緑寄り） |
| 潮麦の指数（生物の星） | 浅瀬（深さ0.3〜2.5m）の群生の量 |
| 嵐の強さ | 空の霞と雲の量、日差しの弱さ |

小魚・捕食者・分解者・栄養は、水面の上からは見えないので、まだ景色に対応させていません（水中のカットを作るときの課題）。

## 地形と構図

- 島は「湾の島（D）」を想定した入り江。中心 (0, 340)、海岸までおよそ 210〜385m、山の高さは最大70m前後。x は東、y は北、z は高さ（m）、海面は z=0。
- 浜の後ろに低くなだらかな平地の帯があり、そこから森の山へ上がる。36°より急な所は「崩れ落ち」（熱侵食）の処理でならし、不自然な壁を残さない。
- 集落は浜沿いの平地（中心 5, 160）に東西に長く並ぶ。家は傾き13°以下の所に、互いに9.5m以上離して置き、家のまわり8mには木を生やさない。桟橋、丸木舟、手前右の小さな岩礁（57, 36）がある。
- 海は深さ60mの水の塊で、深さに応じて赤い光から先に吸収される（浅瀬は砂が透けた青緑、深い所は紺）。水面は影を落とさない設定にして、海底に日が届くようにしている。

## 描画にかかる時間（実測）

どれも、データなし（手つかずの状態）か基準の星・湾の島の場面（木 約2万本、家 31軒）。

| 環境 | 設定 | 時間 |
|---|---|---|
| MacBook Air 13インチ（M5・メモリ16GB）、Blender 5.2.3、`--gpu`（Metal） | 1920×1080・64回 | 1枚 21.7秒（初回だけ GPU の準備で 169秒） |
| Linux の CPU 4コア、Blender 5.0.1 | 1920×1080・256回 | 1枚 649〜801秒（最大メモリ 2.25GB） |
| Linux の CPU 4コア、Blender 5.0.1 | 640×360・16回の動画（240コマ） | 1コマ 約15秒 |

MacBook Air は冷却ファンがないので、長く描き続けると熱で遅くなることがある。

## 限界

- 砕ける波としぶき、雲の立体、動物は未実装。
- 人は MakeHuman の体（CC0。`assets/README.md`）に、姿勢・髪（毛の粒子）・布・肌の材質をこのキットで付けたもの。顔の大写しには向かない（肌の模様の画像を使っていない）。
- 木・家・舟は手続き的に作った簡易なモデル。遠景〜中景向けで、近寄るカットには作り込んだモデルが要る。
- 実写の空・質感（HDRI やテクスチャ）は、この作業環境から素材サイトにつながらなかったため使っていない。使うときは入手元と利用条件を記録する。
